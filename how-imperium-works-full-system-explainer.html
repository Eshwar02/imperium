How Imperium Works

A complete walkthrough — from user login to AI agents writing code and storing results in Supabase.

Big Picture

Imperium is an AI-powered code modernization system. You give it a Git repository URL. It analyses the code, extracts business rules, scores what to change first, and lets AI agents propose code changes — but a human must approve everything at two checkpoints (Gate A and Gate B) before anything is applied.

Think of it as: AI does the analysis and drafts changes — you stay in control of every decision.

1. Authentication (Supabase Auth)

Before anything else, every user must sign in.

1
User visits the app
The frontend (React, running at localhost:5173) detects no session and redirects to /login.
2
Email + Password login
The Login.tsx page calls supabase.auth.signInWithPassword(). Supabase validates credentials from its Auth database (your project: lzwujzkwrsvxxffaybgi).
3
JWT token issued
On success, Supabase returns a JWT access token. The AuthContext stores this in memory and attaches it as Authorization: Bearer <token> on every API call to the backend.
4
Backend verifies the token
Every request to /api/* passes through the verify_jwt middleware (api/auth.py). It uses SUPABASE_JWT_SECRET to verify the token — no valid token, no access.
python-joseHS256

2. The Three Databases

Imperium uses three specialized stores — each for a different purpose:

Supabase / Postgres
Relational metadata. Repositories, modules, business rules, decisions, priorities, timelines, simulations.

Host: aws-0-ap-northeast-1 (Tokyo)
10 tables, migrated via Alembic.
Qdrant
Semantic memory. Vector embeddings of code summaries and business rules. Lets agents search by meaning, not just keywords.

Host: localhost:6333
Neo4j
Call graph. Who calls what. Which files depend on which modules. Used to calculate blast radius of a change.

Host: bolt://localhost:7687

3. The Full Pipeline (Steps 1 → 16)

Once logged in, a user submits a repository URL. The pipeline runs in this order:

1
Ingest the repo
POST /api/ingest — clones the Git repo into the workspace folder, detects languages, stores a Repository row in Postgres.
ingestion/loader.py
2
Build the knowledge base
Parse all source files → build call graph (Neo4j) → embed code summaries (Qdrant) → build git timeline → compute priority scores. All stored in Postgres.
intelligence/parser.pycall_graph.pytimeline.pypriority.py
3
Run 4 Analysis Agents (parallel)
Structure, Business Logic, Security, and Research agents run at the same time (ThreadPoolExecutor). Each talks to a different LLM. Findings are merged and saved to Postgres.
CerebrasNVIDIA NemotronGroqGemini
4
Gate A — Human Approval
The frontend shows findings per category (security, performance, modernization, integration, docs). You approve, reject, or defer each category independently. Votes are saved to the decisions table — append-only, never deleted.
Human in the LoopGateA.tsx
5
Simulate transformations (dry-run)
For approved categories only: the system runs a dry-run simulation — old code → proposed new code → diff → confidence score. If confidence is too low, it blocks and asks you.
intelligence/simulation.py
6
Implementation + Testing agents
Implementation agent writes the actual code changes (one branch per category). Testing agent generates and runs tests to produce a behavioral diff report.
Mistral Codestral
7
Gate B — Pre-Merge Review
You review the actual code diff + the behavioral diff report. Approve to merge, reject to roll back, or request revision. Every vote is recorded in Postgres.
Human in the LoopGateB.tsx
8
Documentation + Comprehension
Documentation agent auto-generates updated docs. Comprehension agent flags high-AI-authorship modules with low team understanding as risks for future review.
agents/documentation.pyagents/comprehension.py

4. The AI Agents

Each agent is a specialist. They each call a different LLM, chosen for their strengths:

Structure Agent
Maps the architecture — modules, dependencies, entry points. Produces the visual structure map shown in the frontend. Uses Cerebras
Business Logic Agent
Extracts hidden business rules from code — "what does this code actually enforce?" Saves rules to Postgres with dedup + versioning. Uses NVIDIA Nemotron
Security Agent
Scans for hardcoded credentials, SQL injection, path traversal, weak auth patterns. Produces security findings. Uses Cerebras
Research Agent
Long-context reasoning — reads the full timeline and business rule history to understand why the code is the way it is. Uses Gemini 2.0 Flash
Implementation Agent
Writes the actual code changes. One branch per approved category. Uses Mistral Codestral
Testing Agent
Generates and runs tests. Produces the behavioral diff report — baseline vs post-change behavior. Uses Mistral Codestral
Documentation Agent
Auto-generates updated documentation from summaries, business rules, and decisions. Uses Groq
Comprehension Agent
Flags modules where AI wrote most of the code but no human has reviewed it — surfaces as a risk for Gate A. Uses Cerebras

7. The Key Principle — Human Always in Control

The system is designed so that no code change can ever be applied without explicit human approval.

Gate A stops the AI before it writes any code.
Gate B stops it before anything merges.
Every vote is stored permanently in Postgres — who approved, when, and why. This is the audit trail.
